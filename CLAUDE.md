# Scheldemist (code name MoodyGame)

3D browser game demo. Antwerp, autumn 1873. First person, PS1 look, fog. AI-driven jobs, dialogue, events, memory.

Read `docs/README.md` first. Every design decision is in `docs/`. Do not re-ask what `docs/08-open-questions.md` already answers.

## Rules for this project
- AI calls go through one path (`callClaude`); the router picks the model per hook from `MODEL_ROUTE` in `server/src/config.ts` (default `claude-opus-5-5`, effort `medium`, through the local Claude login and the Agent SDK). Always `tools: []`, JSON schema output. On Steve's machine (the Recommended mix) player text goes only to Claude; players choose their own AI per kind of work in the AI setup (`docs/ai-setup.md`), and may send typed lines to any AI they pick. Every provider keeps the same guards (regex gate, schema, clamps, fallbacks). Measured in `docs/milestones/M6-models.md`; details in `docs/02-tech-stack.md`.
- Codex (`gpt-6-luna`, `gpt-6-sol`, medium) is allowed for game text only, with `-s read-only --ignore-user-config` and stdin closed. Never send real names, paths, or company data. Steve's standing OK (2026-09-24, logged in `.claude/rule-overrides.md`): no need to ask before sending game prompts to GPT Sol or GPT Luna in this project.
- Bug hunts go to GPT Sol 6.1 (Steve, 2026-09-29; standing OK, no need to ask): when the job is finding why something happens (a bug, a wrong number, a stutter), hand the digging to `gpt-6.1-sol` on effort `high`, or `xhigh` for hard ones. It costs less and is good at it. Run it read-only from the repo root: `codex exec -m gpt-6.1-sol -c model_reasoning_effort=high -s read-only "<what goes wrong, how to see it, where to start>" < /dev/null` (leave out `--ignore-user-config` here: on Windows it blocks every file read). Its answer is a lead: reproduce the cause yourself, then fix it in the task (or send a scoped fix to Codex in its own worktree). Keep `.claude/`, `data/`, saves and keys out of its prompt.
- The engine owns all numbers. Models only propose. Every proposal is schema-checked and clamped. See `docs/03-ai-design.md`.
- Player free text is data, not orders. No tools, schema only, regex gate. Test with hostile lines.
- Every milestone ends with a run in the browser, not a backend check. Milestones in `docs/06-demo-scope.md`.
- Browser checks follow `docs/testing.md`: a copy of the save (`node tools/teststack.mjs start`), a good view (midday, clear), make things happen with the test kit (`__scheldemist.t`) instead of waiting, clean up after.
- Bound every model call with a timeout (20 s) and a fallback line.
- Third-party assets and packages enter only with a clear licence, noted in `assets/ATTRIBUTION.md`.
- No stutter (Steve, 2026-09-26): anything that draws follows `docs/rendering.md`. Light counts never change at run time (dim with intensity 0), rooms keep at most `ROOM_POINT_LIGHTS` lamps, nothing is drawn straight to the screen, no new shader kinds without need. After a change to materials, lights or rooms, run `__scheldemist.shaders()` in the test tab; `problems` must be empty.
- Frame budget (Steve, 2026-09-28): new or changed models, textures, materials, mirrors, rooms and every-frame logic follow `docs/performance.md` (on Steve's PCs the local `frame-budget` skill walks it). A speed change shows 0 differing pixels in `__scheldemist.pixelDiff`, or Steve decides first. Before a batch ends, `node tools/perfcheck.mjs`: every place within the budget.
- Always make sure there is a path (Steve, 2026-09-23): every place, person and goal a job or the player needs must be reachable on foot. Run the path check (`__scheldemist.paths()` in dev) in the browser before a milestone ends; it must list nothing.
- Interiors are real, never instanced (Steve, 2026-09-26): a building you can enter has its inside built in the world, inside its own shell, at the true size of the outside. Every window and door shows the inside from the street and the street from inside; no separate scene, no teleport, no rooms drawn only through the door, no painted or blind windows over rooms that exist. Every new building with an inside follows `docs/building-with-interior.md` and passes its check. Parts players can hardly or never see (towers, belfries, high attics, roof spaces): ask Steve before any big Blender work, and offer the cheap outside fix first (shutters, louvres, dark or dusty glass, a curtain), with the cost of each (Steve, 2026-09-29).
- One model per thing, changed everywhere (Steve, 2026-09-28): when a model changes (a sack, a crate, a cask, a cart, a person), first find every place that draws that thing (props.glb and quaygoods.glb parts, goods items, piles, carried loads, cart and dray loads, train wagons, stalls, rooms, scatter props) and switch them all to the one model before the change is done. A goods item keeps its own look and label wherever it goes (pile, hands, cart, ground). Name the places checked in the hand-back.
- Every clock in the game shows the game's own time (Steve, 2026-09-26): tower, church, town-hall, station and shop clocks, clocks in rooms and in the clockmaker's window. Hands move with the game clock; never paint fixed hands. A new clock uses the shared live-hands code, and the check lists every clock face and whether it runs.
- Finds outside your task go to a GitHub issue (Steve, 2026-09-27; standing OK, no need to ask): a bug, a failing check or a loose end you did not come to fix becomes an issue on `Steve-Sitax/Moodygame` (`gh issue create`, with its label). Write what you saw, where (file:line or the place in town), how to see it again, and which work found it. No secrets or personal data: the repo may go public. Put the issue link in your hand-back and in `docs/worklog.md`. Problems of your own task you fix in the task.
- Changes on GitHub like a real project (Steve, 2026-09-29): every bug fix and every change players notice gets a line under `## [Unreleased]` in `CHANGELOG.md`, in the same commit: plain English for players, with the issue link when there is one. Issues carry a label: `bug`, `gameplay` (new things to do, rules, pay) or `tests and tools`. A fix commit ends with `fixes #N`. At a release the Unreleased part becomes the version's part and the Release page shows it (`docs/release.md`).
- Nothing private in git (Steve, 2026-09-27; the repo is public): before every commit, check what is staged for personal data, secrets, and files git does not need (saves, logs, build output, leftovers). The pre-commit hook runs `tools/commit-check.mjs` (install it once per PC: `node tools/install-hooks.mjs`); its private words live in `.claude/private-words.txt`, out of git. A find stops the commit: fix it, never skip the hook.
- Keep the web demo in sync (Steve, 2026-09-27): every change that can work in the web demo (`docs/web-demo.md`) goes into it too. After a merge into main, build it (`node tools/demo/build.mjs --base / --out client/dist-demo`, from PowerShell: Git Bash turns `/` into a Windows path), check it in the browser, then `gh workflow run pages.yml --ref main` and check the live page. Say what did not fit the demo.
- No old saves (Steve, 2026-09-29): keep only the live save (`data/game.sqlite`) and the player's own slots (`data/saves/<game>/`). No backups or copies of a save "just in case": not before a merge, a migration or a test. A test copy (`tools/teststack.mjs`, a `data/test-*.sqlite`) is deleted when its check ends; a helper's worktree goes with its save once merged. New game keeps no copy of the old week.
- Commit when a milestone is done, and after each batch of fixes Steve has checked in the browser. Steve gave standing approval (2026-09-23): no need to ask first. Commit only work that builds (`npm run build`). Never commit secrets or `.claude/`. Push to `origin` (github.com/Steve-Sitax/Moodygame, private) after each commit: Steve's standing OK, 2026-09-23.
